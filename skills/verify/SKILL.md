# /verify — 验证 + 汇总报告

## 概述

委托 verifier agent 运行测试和覆盖率检查。如果失败则委托 executor agent 进行修复，然后重新验证，最多 3 轮循环。全部通过后，汇总全流程产出报告并给出最终质量评分（A/B/C/D/F）。

对应完整流水线 Phase 8。

## 执行流程

### Step 1: 委托 verifier agent 全面检查

委托 **oh-my-costrict:verifier** agent 执行以下检查：

1. **测试运行**：
   - 找到项目中的测试文件
   - 运行项目测试命令（package.json scripts 中的 test）
   - 收集测试结果（通过/失败数量、失败详情）

2. **覆盖率检查**：
   - 运行覆盖率命令
   - 验证是否达到 80%+ 覆盖率目标
   - 对于未覆盖的代码路径，输出覆盖盲区列表

3. **Lint / TypeCheck 检查**：
   - 运行 lint 命令
   - 运行类型检查命令

### Step 2: 判断结果 → 修复循环（最多 3 轮）

```
verifier 检查
    │
    ├─ 全部通过 → 输出验证报告，进入 Step 3（汇总报告）✅
    │
    └─ 有失败项 → 委托 executor agent 修复
                    │
                    └─ 重新验证（verifier）
                         │
                         ├─ 全部通过 → 进入 Step 3 ✅
                         │
                         └─ 仍有失败 → 继续修复/重验证
                              │
                              └─ 超过 3 轮 → 报告阻塞 ❌
```

详细规则：
- **测试失败** → executor 分析失败原因并修复，verifier 重新运行测试
- **覆盖率不足** → executor 编写补充测试，verifier 重新检查覆盖率
- **Lint 失败** → executor 修复 lint 问题，verifier 重新运行 lint
- **TypeCheck 失败** → executor 修复类型错误，verifier 重新运行类型检查
- 每轮修复后输出修复摘要
- 超过 3 轮仍未全部通过 → 报告阻塞并请求人工介入

### Step 3: 汇总全流程报告

验证全部通过后，自动收集全流程（Phase 1-8）的所有产出，生成汇总报告。

```
输入收集：
  ├─ Phase 1 产出：PRD 文档
  ├─ Phase 2 产出：UI 设计审查报告（如触发）
  ├─ Phase 3 产出：技术方案 + ADR
  ├─ Phase 4 产出：子任务列表
  ├─ Phase 5 产出：代码 + 测试 + TDD 报告
  ├─ Phase 6 产出：审查报告（含 DX 审查）
  ├─ Phase 7 产出：修复记录
  └─ Phase 8 产出：验证结果（测试 + 覆盖率 + lint/typecheck）
         │
         ▼
    汇总报告 + 质量评分
```

## 使用方式

```bash
# 在 workflow 流水线中自动触发（Phase 8）
/oh-my-costrict:workflow 实现用户认证系统

# 独立调用 — 验证指定路径的代码
/oh-my-costrict:verify src/components/

# 独立调用 — 验证全部代码
/oh-my-costrict:verify .
```

## 注意事项

- 委托 verifier agent，不要自行验证
- 修复循环最多 3 轮，超过则报告并等待人工决策
- 每轮修复后必须重新验证全部项目（不单独验证修复部分）
- 独立调用时仅输出验证报告（无全流程汇总）
- 在 workflow 流水线中调用时，自动收集前置 Phase 产出生成汇总报告
- 汇总报告中的质量评分必须基于各 Phase 的实际产出，不可凭空给出
- 所有输出使用中文
