# /costrict-autopilot — 自动审查流水线

## 概述

全自动质量门流水线，依次执行以下六个阶段（非 UI 任务跳过 Phase 2a），每个阶段产出一个审查报告，最终汇总为完整的质量评估。

## 自动化触发

用户只需发起一次命令，后续所有阶段自动执行：

```
/costrict-autopilot <任务描述>
```

流水线自动检测任务类型并执行相应阶段，无需任何手动干预。

## 执行流程

### Phase 1: PRD 生成（grill-me 内置）

- 委托 **planner** 代理分析任务需求
- **grill-me 模式自动激活**：planner 以 ruthless interview 方式探索需求
  - 每次只问一个问题，附带推荐答案
  - 走完决策树的每个分支
  - 能用代码库回答的问题优先探索代码库
- 产出一份结构化的 PRD 文档，包含：目标、范围、验收标准、技术约束、决策记录
- 输出格式：markdown 文档到任务目录

### Phase 2a: UI 设计审查（自动检测触发）

**触发条件**：任务描述中包含以下任一关键词时自动执行
- 前端关键词：frontend、前端、UI、界面、页面、组件、样式、布局
- 产品类型：dashboard、仪表盘、landing page、落地页、website、网站、mobile app、移动应用
- 技术栈：React、Vue、Next.js、Tailwind、shadcn/ui、React Native、Flutter

**执行内容**（委托 ui-ux-pro-max 技能）：
1. 分析产品类型、目标受众、风格关键词
2. 生成设计系统推荐（风格、调色板、字体配对、间距、圆角、阴影）
3. 按优先级执行 UX 审查（可访问性 → 触摸交互 → 性能 → 风格 → 布局 → 排版 → 动效 → 表单 → 导航）
4. 检查跨规范一致性
5. 输出 UI 设计审查报告

**跳过条件**：纯后端任务（CLI 工具、API、数据库、脚本）自动跳过本阶段。

### Phase 2b: 架构设计审查（始终执行）

**执行内容**（委托 grill-with-docs 技能）：
1. 加载项目 spec 体系（.trellis/spec/）和 CONTEXT.md 建立领域认知
2. 术语挑战：检查 PRD 术语与 CONTEXT.md 的一致性，精确化模糊术语
3. 领域关系挑战：用具体场景压力测试领域关系
4. 架构决策挑战：每个架构选择追问为什么选 A 不选 B
5. 代码库一致性验证：验证 PRD 中的声明与实际代码一致
6. 内联更新 CONTEXT.md（术语确定后立即写入）
7. 按需生成 ADR（满足三条件：难以逆转 + 缺少上下文会困惑 + 真正做过取舍）
8. 输出架构设计审查报告

### Phase 3: 工程审查

- 委托 **reviewer** 代理审查代码实现
- 检查点：代码质量、命名规范、错误处理、性能、安全
- grill-with-docs 的术语/架构决策作为审查输入
- 输出：工程审查报告（CRITICAL/HIGH/MEDIUM/LOW 分级问题列表）

### Phase 4: DX 审查（开发者体验）

- 委托 **reviewer** 代理审查开发者体验
- 检查点：API 易用性、文档完整性、错误信息友好度、配置复杂度
- 输出：DX 审查报告（改进建议列表）

### Phase 5: 汇总报告

- 汇总前五个阶段（或四个，如跳过 Phase 2a）的审查结果
- 生成最终质量评估报告，包含：
  - 各阶段通过/失败状态
  - 设计系统推荐摘要（如有 UI 审查）
  - 新增/更新的术语（来自 grill-with-docs）
  - 新增的 ADR（来自 grill-with-docs）
  - 问题汇总（按严重程度排序）
  - 改进建议优先级列表
  - 整体质量评分（A/B/C/D/F）

## 使用方式

```bash
# 全功能任务（自动包含 UI + 架构设计审查）
/costrict-autopilot 实现用户仪表盘页面，包含数据图表和用户设置表单，支持深色模式

# 纯后端任务（自动跳过 UI 设计审查）
/costrict-autopilot 实现用户认证 API，包含 JWT 令牌管理和密码加密

# CLI 工具（自动跳过 UI 设计审查）
/costrict-autopilot 实现数据迁移 CLI 工具，支持增量迁移和回滚
```

## 自动检测规则

流水线启动时自动判断执行哪些阶段：

```
任务描述分析
  │
  ├─ 包含 UI/前端关键词？
  │   ├─ 是 → Phase 2a (UI 设计审查) + Phase 2b (架构设计审查)
  │   └─ 否 → Phase 2b (架构设计审查) only
  │
  └─ 始终执行：Phase 1 (PRD) + Phase 3 (工程审查) + Phase 4 (DX 审查) + Phase 5 (汇总)
```

## 注意事项

- 每个阶段独立执行，前序阶段的输出作为后续阶段的输入
- 任一步骤失败（审查结果为"拒绝"）则终止后续步骤并报告
- grill-me 已内置在 Phase 1 的 brainstorm 流程中，无需额外配置
- ui-ux-pro-max 和 grill-with-docs 为新增阶段，自动触发无需手动调用
- 所有代理使用 CSC 默认模型，无需手动指定
- CONTEXT.md 和 docs/adr/ 按需惰性创建（第一个术语/ADR 产生时才创建文件）
