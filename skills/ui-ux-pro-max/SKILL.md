# /ui-ux-pro-max — UI/UX 设计智能

## 概述

基于 nextlevelbuilder/ui-ux-pro-max-skill 的 UI/UX 设计智能引擎，适配 oh-my-costrict 的自动化流水线。在 UI 相关任务的设计阶段自动触发，生成设计系统推荐并审查 UI 质量。

## 触发时机

以下情况**自动触发**（无需用户手动调用）：

| 触发条件 | 触发方式 |
|----------|----------|
| `/oh-my-costrict:workflow` 任务涉及 frontend/UI/界面/页面/组件 | 自动作为 UI 设计阶段执行 |
| 任务描述含关键词：页面、界面、UI、前端、组件、样式、布局、仪表盘、落地页 | 自动检测触发 |
| 用户明确请求 UI 设计审查 | 手动触发 |

以下情况**自动跳过**：
- 纯后端任务（CLI 工具、API、数据库、脚本）
- 任务描述中无任何前端/UI 相关关键词

## 核心能力

### 设计系统生成

根据产品类型和行业自动推荐：

| 维度 | 数据量 | 示例 |
|------|--------|------|
| **风格** | 50+ | 极简主义、玻璃态、新粗野主义、Bento Grid、暗黑模式... |
| **调色板** | 161 | 按行业/产品类型匹配（金融蓝、医疗绿、SaaS紫...） |
| **字体配对** | 57 | 标题+正文配对（Inter+Source Serif、Geist+Geist...） |
| **UX 准则** | 99 | 覆盖可访问性、触摸交互、性能、动效、表单、导航... |
| **产品类型** | 161 | SaaS、电商、仪表盘、落地页、博客、移动应用... |

### UX 审查维度（优先级排序）

#### Priority 1: 可访问性 (CRITICAL)
- 颜色对比度 ≥ 4.5:1（正文）/ 3:1（大文本）
- 可见焦点环（2-4px）
- 图片 alt 文本
- 键盘导航支持
- 图标按钮须有 aria-label
- 支持 prefers-reduced-motion
- 颜色不是唯一的信息传递方式

#### Priority 2: 触摸与交互 (CRITICAL)
- 最小触摸目标 44×44px
- 触摸目标间距 ≥ 8px
- 异步操作有加载反馈
- 错误信息在问题旁显示
- 不依赖 hover 做主要交互

#### Priority 3: 性能 (HIGH)
- 图片用 WebP/AVIF 格式
- 懒加载非关键资源
- 预留空间防止布局偏移 (CLS < 0.1)
- 字体加载用 font-display: swap
- 列表超过 50 项须虚拟化

#### Priority 4: 风格选择 (HIGH)
- 风格匹配产品类型
- 全局风格一致性
- 图标用 SVG（Heroicons/Lucide），不用 emoji
- 明暗模式配对设计

#### Priority 5: 布局与响应式 (HIGH)
- 移动优先断点（375 / 768 / 1024 / 1440）
- viewport meta 正确设置
- 无水平滚动
- 4pt/8dp 间距系统
- 桌面容器用 max-w-6xl / 7xl

#### Priority 6: 排版与颜色 (MEDIUM)
- 基础字号 16px
- 行高 1.5-1.75
- 语义化颜色 token（非裸 hex）
- 暗黑模式用去饱和浅色变体

#### Priority 7: 动效 (MEDIUM)
- 微交互 150-300ms
- 只用 transform/opacity 做动画
- 进场 ease-out，退场 ease-in
- 每次动画有因果意义

#### Priority 8: 表单与反馈 (MEDIUM)
- 每个输入有可见 label
- 错误在字段下方显示
- 提交有 loading → success/error 反馈
- 失焦时校验（非按键时）
- 破坏性操作有确认

#### Priority 9: 导航 (HIGH)
- 底部导航 ≤ 5 项
- 返回行为可预测
- 关键页面支持深链接
- 大屏侧边栏 / 小屏底部导航

#### Priority 10: 图表与数据 (LOW)
- 图表类型匹配数据类型
- 色盲友好配色
- 数据表格作为图表替代
- 图例始终可见

## 执行流程

### Step 1: 分析任务需求

从 PRD 中提取：
- **产品类型**：SaaS / 电商 / 仪表盘 / 落地页 / 博客 / 移动应用 / 其他
- **目标受众**：B2B / B2C / 开发者 / 企业内部
- **风格关键词**：现代 / 专业 / 活泼 / 极简 / 奢华 / 科技感
- **技术栈**：React / Vue / Next.js / Tailwind / shadcn/ui / React Native / Flutter

### Step 2: 生成设计系统推荐

基于产品类型和风格关键词生成设计系统（纯指令模式，不依赖外部脚本）：

```markdown
## 设计系统推荐

### 风格方向
- **主风格**：<推荐风格> — <理由>
- **备选风格**：<备选> — <适用场景>

### 调色板
- **主色**：<hex> — <用途>
- **辅色**：<hex> — <用途>
- **强调色**：<hex> — <用途>
- **成功/错误/警告**：<hex> / <hex> / <hex>
- **中性色阶**：50/100/200/.../900

### 字体配对
- **标题字体**：<字体名> — <理由>
- **正文字体**：<字体名> — <理由>
- **后备字体**：<系统字体栈>

### 间距系统
- **基准**：4px / 8px
- **间距阶**：4, 8, 12, 16, 24, 32, 48, 64, 96

### 圆角
- **小**：4px（按钮、输入框）
- **中**：8px（卡片）
- **大**：12px（模态框）
- **全圆**：9999px（药丸形）

### 阴影层级
- **1 级**：卡片悬浮
- **2 级**：下拉菜单
- **3 级**：模态框
```

### Step 3: UX 审查

按优先级顺序（1→10）逐条检查 PRD 中的 UI 需求和验收标准：

```
对每个 Priority Level：
1. 列出适用的检查项
2. PRD 中是否已覆盖？→ ✅ 已覆盖 / ⚠️ 缺失 / ❌ 违规
3. 缺失项 → 提出具体补充建议
4. 违规项 → 标记为必须修复
```

### Step 4: 跨规范一致性检查

验证设计方案与项目现有规范的一致性：
- 组件命名是否与现有模式一致？
- 样式方案是否与 .trellis/spec/frontend/ 规范兼容？
- 技术栈选择是否与现有项目一致？

### 风格与一致性审查 (Priority 4-5)
...

### 排版与颜色审查 (Priority 6)

## 常用设计 token 参考

### SaaS 产品典型方案
- 风格：极简 + 微妙的阴影
- 调色板：Indigo 主色 + Cool Gray 中性色
- 字体：Inter（正文）+ Inter（标题）
- 圆角：6-8px 全局

### 仪表盘/管理后台
- 风格：数据优先 + 信息密度高
- 调色板：Slate 主色 + Blue 强调色
- 字体：Inter 或 system font
- 圆角：4-6px（紧凑）

### 落地页/营销站
- 风格：大胆排版 + 渐变 + 动效
- 调色板：品牌色为主 + 高对比
- 字体：Display 字体（标题）+ 易读正文
- 圆角：8-16px（柔和）

### 移动应用
- 风格：平台原生感（iOS HIG / Material Design）
- 触摸目标：≥ 44pt (iOS) / 48dp (Android)
- 安全区域：注意 notch / 灵动岛 / 手势条
- 字体：SF Pro (iOS) / Roboto (Android)

## 注意事项

- 纯指令模式运行，不依赖外部 Python 脚本
- 如果用户已安装 ui-ux-pro-max 原始技能，优先使用其 search.py 脚本获取更精准的推荐
- 设计系统推荐基于常见最佳实践，应结合项目实际约束调整
- 所有输出使用中文
- 跳过明确非 UI 的任务（纯后端、CLI、脚本）
