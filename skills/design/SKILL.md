# /design — 架构设计 + 审查

## 概述

委托 architect agent 设计技术方案，内置 grill-with-docs 挑战技术选型和架构决策，必要时生成 ADR。方案产出后进入 Gate 检查，列出关键架构决策询问用户确认。此命令对应完整流水线 Phase 3。

## 执行流程

### Step 1: 读取输入文档

收集全量输入：
- **PRD 文档**（Phase 1 产出）：需求范围、验收标准、技术约束
- **UI 设计审查报告**（Phase 2 产出，如有）：设计系统推荐、UX 准则

### Step 2: 委托 architect agent

委托 **oh-my-costrict:architect** agent 基于输入文档设计技术方案。

architect 应产出：
- **系统架构**：模块划分、组件关系、数据流
- **接口设计**：API 契约、数据模型、组件接口
- **技术选型**：框架、库、工具选择及理由（含备选方案对比）
- **安全架构**：认证/授权方案、数据保护
- **扩展性评估**：未来变更的影响范围

### Step 3: grill-with-docs 领域验证（内置）

在 architect 产出技术方案后，自动执行 grill-with-docs 领域验证：

1. **术语一致性检查**：方案中的术语是否与 CONTEXT.md 对齐
2. **领域关系压力测试**：用具体场景验证领域关系是否合理
3. **架构决策挑战**：对每个架构选择追问"为什么选 A 不选 B"
4. **代码库一致性验证**：方案中的声明是否与现有代码一致
5. **ADR 生成**：满足三条件（难以逆转 + 缺少上下文会困惑 + 真正做过取舍）时生成 ADR

### Step 4: 输出技术方案草稿

将 architect 产出的方案 + grill-with-docs 验证结果合并，输出为技术方案草稿。

### Step 5: 🚦 Gate 检查 — 关键架构决策确认

技术方案草稿输出后，列出以下关键架构决策，询问用户确认：

```
🚦 设计 Gate — 请确认以下关键架构决策：

1. **技术选型**：
   - <选型1>：选择了 <方案>（备选：<方案B>），理由...
   - <选型2>：选择了 <方案>（备选：<方案B>），理由...
   是否同意上述选型？

2. **模块划分**：模块职责和依赖关系是否合理？是否有遗漏的模块？

3. **数据模型**：核心实体和关系是否准确？是否满足 PRD 中的需求？

4. **ADR 决策**（如有）：
   - ADR-XXXX: ... — 是否同意此决策？

5. **grill-with-docs 验证结果**：验证中发现的问题是否已正确处理？

请回复：
- "通过" / "确认" → 方案定稿，进入下一阶段
- "修改 <具体修改意见>" → 根据意见修改方案并重新 Gate
- "终止" → 结束流程，保留当前技术方案文档
```

**Gate 规则**：
- 用户全部确认 → 技术方案定稿，进入 Phase 4
- 用户要求修改 → 回到 architect 按意见修改，修改后重新 Gate
- 用户选择终止 → 结束流程，输出已产生的技术方案文档
- Gate 循环次数不限，直到用户确认通过或选择终止

## 使用方式

```bash
# 在 workflow 流水线中自动触发（Phase 3）
/oh-my-costrict:workflow 实现用户认证系统

# 独立调用
/oh-my-costrict:design docs/prd/user-auth.md
```

## 注意事项

- 委托 architect agent，不要自行设计方案
- grill-with-docs 领域验证是内置步骤，自动执行
- ADR 仅在满足三条件时生成，不为每个决策生成
- Gate 检查必须列出具体的架构决策（含备选方案对比），而非简单的是/否问题
- Gate 不通过时提供明确的修改方向
- 所有输出使用中文
